# Negative Prompt Intelligence Engine

The negative / avoid list in prompt-king is generated by an engine, not a
throwaway tail. The canonical vocabulary lives in `SKILL.md` (section
`NEGATIVE PROMPT INTELLIGENCE ENGINE`); this file is the design rationale and
pointer, so the vocabulary never drifts between two copies.

## The pipeline

```
REQUEST → CONTENT TYPE → FAILURE MODE MATCH → CATEGORY → NEGATIVE VOCABULARY →
PLATFORM FILTER → CONFLICT CHECK → FINAL NEGATIVE PROMPT
```

Each step is defined in full in [`SKILL.md`](../SKILL.md). The key idea: the
avoid list must be matched to the deliverable's actual failure modes, exactly
as the positive command selection is matched to its intent. A book cover's
risks are not a product shot's risks.

## Versioned knowledge base

The base is versioned per category snapshot:

- `NEG-V1 (2026-08-09)` — baseline. Full category list in
  [`SKILL.md`](../SKILL.md).

Version is surfaced with every output ("Negative base: NEG-V1") so a failure
traces to exactly which vocabulary was in play.

## Learning path

Repeated failures tied to a negative-prompt gap are recorded by
[`SESSION CLOSE`](../SKILL.md). Once they meet the
[promotion gate](self-improvement-engine.md#promotion-gate), the fix becomes a
versioned addition (`NEG-V2+`). The engine never rewrites its own base from a
single session — same human-gated rule as the rest of the skill.
