# Prompt King — Architecture

Prompt King is a Claude Code skill that turns a vague request ("I need a cover
for my book") into a production-ready image or video prompt. It works as a
three-stage pipeline, with a mandatory closing review loop.

## The pipeline

1. **Interview** — On a vague brief, the skill asks 1–3 targeted questions to
   fill only the gaps that cannot be reasonably inferred. A clear brief skips
   this stage entirely.

2. **Research** — When the request names a platform or model whose behavior may
   be stale (e.g. Veo 3, Kling), the skill verifies current facts live and
   attaches a source + date to every researched claim. No browsing tool, or no
   source found → it says so instead of inventing details. Skipped when the
   request uses only well-established, built-in knowledge.

3. **Direct** — The skill selects commands from the master libraries (image
   command library, video intelligence system, typography/format/quality
   directives) and assembles a structured production prompt with subject,
   visual language, composition, camera, lighting, typography, aspect ratio,
   and an avoid-list.

4. **Self-critique loop** — After every draft, a fixed review pass checks for
   ambiguity, conflicts, redundancy, and specificity before the prompt is
   returned. Unresolvable conflicts are surfaced to the user rather than
   silently resolved. Includes a NEGATIVE CHECK (does the avoid list conflict
   with any positive instruction?).

## The negative prompt engine

Every production prompt carries a content-type-matched, conflict-checked
negative/avoid list generated by the **NEGATIVE PROMPT INTELLIGENCE ENGINE** —
not a generic throwaway tail. The base is versioned (`NEG-V1` baseline), and
repeated failures feed versioned additions through the self-improvement path.
See [`docs/negative-prompt-engine.md`](negative-prompt-engine.md).

## The self-improvement engine

The skill records failures at SESSION CLOSE and learns through a 13-stage,
human-gated pipeline (OBSERVE → RECORD → … → PROMOTION GATE → … → MONITOR).
Canonical behavior is human-owned: the engine observes, records, and
recommends, but **never self-edits** — promotion requires a detected pattern,
benchmark pass, clean regression, and explicit human approval.
See [`docs/self-improvement-engine.md`](self-improvement-engine.md).

## Where things live

- `SKILL.md` — the entire system: pipeline, protocols, and command libraries.
  Single source of truth.
- `prompt-king.md` — the tool-agnostic copy-paste version (same content,
  no Claude Code references).
- `reference/image-commands.md`, `reference/video-commands.md`,
  `reference/negative-prompt-engine.md` — indexes into the SKILL.md sections.
- `reference/platform-cheatsheets.md` — sourced, dated notes on video platforms.
- `docs/self-improvement-engine.md`, `docs/negative-prompt-engine.md` — engine
  design rationale.
- `examples/` — before/after prompt examples.
- `tests/eval-suite.md` — the regression scenarios the pipeline must pass.
- `tests/adversarial-suite.md` — attacks the self-improvement loop must repel.
- `data/` — the self-improvement memory layer (experiences, preferences,
  hypotheses, versions, invariants). `rules/` holds validated, promoted rules.
- `scripts/sync-to-claude.sh` — installs the skill into Claude Code.
- `scripts/snapshot.ps1`, `scripts/rollback.ps1` — version + rollback the
  installed skill copy. `scripts/record-experience.ps1`,
  `scripts/detect-patterns.ps1`, `scripts/promote-rule.ps1` — the learning
  harness.
